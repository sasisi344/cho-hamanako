# 読み進めてもらう書き方（タイトル・冒頭・見出し・節のつなぎ）

作成: 2026-11-15（hq:H-45）／対象: 新規記事とリライトの両方／読む人: 記事を書く実行者（Codex）と検収する CC

この文書は「検索結果で選ばれ、最後まで読まれ、記事の途中の広告とカードが画面に入る」ための書き方の正本。文体・記法は [writing-style/SKILL.md](writing-style/SKILL.md)、構成の部品は [base-article-structure/SKILL.md](base-article-structure/SKILL.md)、カードの置き方は [affiliate-placement-rules.md](affiliate-placement-rules.md) が正本で、この文書はその上に重ねる。

**優先順位**: 事実の正確さ・法令・「筆者の体験を創作しない」 ＞ この文書 ＞ 文字数の目安。この文書の技法を使うために事実を足したり、体験を作ったりしない。

## 1. なぜ必要か（2026-10-06〜11-14 の実測）

PV 30 以上の47記事を調べた結果。データは `.workspace/access-data/api/2026-11-15-write-engage/`・`write-scroll90/`・`write-gscpage/`。

| 見たもの | 結果 |
|---|---|
| 1人あたりの滞在時間 | 平均95秒。記事の平均は約4,500字で、通読には約9分かかる。読まれているのは2割ほどで、多くの読者は見出しを拾って流し読みしている |
| 記事の最後まで届いた人（90%スクロール） | 全体で32% |
| 文字数と最後まで届いた人 | 2,500字未満 42%／2,500〜4,000字 37%／4,000〜6,000字 31%／6,000字以上 14% |
| タイトルの長さ | 平均37字。47本中37本が32字を超え、検索結果で後ろが切れている |
| 見出し（H2） | 「ポイント概要と詳細アクセス」のような分類名が多い。問いの形の H2 は1記事あたり0.6個 |
| 本文の画像 | 1記事あたり0.2枚 |

読者は「読む」より先に「見出しを拾う」。そのため、見出しだけを追っても話が分かり、拾った見出しの直下に答えがあることが、読み進めてもらう条件になる。

## 2. 広告とカードが入る位置（書き手が知っておくこと）

広告は記事の見出しの位置に自動で入る。書き手が広告のコードを書くことはない。

| 枠 | 入る位置 |
|---|---|
| 1つ目 | 最初の H2 の直後 |
| 記事の途中 | 4つ目の H2 の前と、7つ目の H2 の前（それが最後の H2 でないとき） |
| まとめの前 | 最後の H2 の前（途中の枠から H2 が2つ以上離れているとき） |
| 記事末 | 関連コンテンツの枠 |

ここから決まる書き方の決まり:

1. **H2 は5〜8個にする。** 4個以下だと記事の途中の枠が入らない。9個以上は節を統合する（多すぎる見出しは流し読みでも追えない）
2. **H2 の直前を TackleCard で終わらせない。** カードの直後には広告が入らない作りになっている。カードの後ろに、次の節へつなぐ1文（§6）を置く
3. **最初の H2 までを短くする（§4）。** 1つ目の枠と、その下の答えに早く届かせる
4. **広告のために中身を薄めない。** 見出しを増やすためだけの節、答えを後ろへ回す構成は禁止（§8）

## 3. タイトルと summary

リライトでは、タイトルと `summary` も見直しの対象にする。`slug` は変えない。

### タイトルの決まり

1. **30〜34字を目安、36字を上限**にする。検索結果で切れない長さ
2. **先頭15字以内に、検索される言葉を入れる**（場所名・魚種名＋知りたいこと）。区切りの `｜` は1つまで
3. **後半には、この記事にしかない具体的な中身を1つ入れる**（数・時期・条件・答えの一部）。例: 「T字堤の何番？」「7選」「駐車場は何時まで」
4. **使わない語**: 「完全ガイド」「完全攻略」「徹底解説」「完全網羅」「必見」「まとめ」だけで終わる後半、`～〜` で囲む飾り、【】の多用。中身が伝わらず、どの記事も同じに見える
5. **読みがなをタイトルに入れない。** 「村櫛漁港（むらくしぎょこう）」の読みは本文の最初に書く
6. タイトルに書いた数・答えは、本文に必ずある（数が合わない、答えが載っていないタイトルは禁止）

### 記事の種類ごとの型

| 種類 | 型 | 例（既存の記事の事実で組んだもの） |
|---|---|---|
| ポイント単体 | 場所名＋「釣り」＋｜＋その場所だけの判断材料 | 新居海釣り公園の釣りポイント｜サビキ・青物・タコはT字堤の何番？ |
| ポイントまとめ | 「浜名湖」＋条件＋数＋｜＋選ぶ軸 | 浜名湖 家族で行きやすい釣り場7選｜車横付け・駐車場・トイレで選ぶ |
| 魚種・釣り方 | 「浜名湖」＋魚種＋知りたいこと＋｜＋時期か場所の具体 | 浜名湖アジング 常夜灯ポイント｜場所・時間帯・釣り方 |
| 月・季節 | 月＋「浜名湖」＋釣れる魚の名前 | 11月の浜名湖釣り｜カレイと落ちシーバスの狙い方 |
| ルール・知識 | 問いに答える形（〜は禁止？／〜はいつまで？） | 浜名湖 集魚灯の使い方｜禁止？合法？仕組みとコツ |
| 料理 | 魚種＋「食べ方」＋｜＋結論の一部 | キビレの食べ方｜刺身より加熱をすすめる理由とレシピ |

### 変えるときの手順（リライト）

- 指示書に「タイトル: 変えない」とある記事は変えない。検索の CTR が高い記事は、CC が指示書で止める
- それ以外は、決まりに沿った案を**3つ**作り、第1案を反映する。3案と、元のタイトルから変えた理由を報告書に書く
- 元のタイトルにある検索される言葉（場所名・魚種名・「駐車場」など）は、新しいタイトルでも落とさない

### summary

- 70〜120字。**1文目で、検索した人の問いに答える**（「〜は〇〇です」）。2文目で、この記事で分かることを2〜3個挙げる
- 「解説します」「紹介します」で終わる文だけにしない。「3,000字超の大ボリューム」のような量の自慢は書かない

## 4. 冒頭（最初の H2 まで）

1. **300字以内**にする。500字を超えない
2. **最初の2文で、読者の場面か問いを置く。** 「『釣！浜名湖』へようこそ」のあいさつから始めない
   - 場面の例: 「朝、テントのジッパーを開けたら、目の前が釣り場。」（渚園の記事）
   - 問いの例: 「新居弁天のライブカメラが見られなくなって、困っていませんか。」
   - ここで書くのは**読者の**場面。筆者の釣行は書かない（体験の創作になる）
3. **次に、答えを1〜2文で言う。** 続けて「こんな人に向いています」か「この記事で分かること」を箇条書き3〜4個で置く
4. **冒頭に BlogCard・TackleCard・大きな表を置かない。** 読者が最初の H2 に届く前に別のページへ出てしまう。ほかの記事への案内は、関係する節の中か記事の後半に置く
   - 例外: ポイント記事の `<Map>` と `<GMapButton>` は、これまでどおり冒頭に置く
5. 答えの表（早見表）は、**最初の H2 の中**に置く

## 5. 見出し（H2・H3）と、その直下の1〜2文

検索エンジンと AI の回答は、見出しとその直下の文を抜き出して使う。流し読みの読者も同じところを読む。

1. **H2 は分類名ではなく、読者の問いか、答えの要点にする。** 場所名・魚種名を入れる
   - ×「ポイント概要と詳細アクセス」 → ○「渚園の駐車場とトイレ｜どこに停めて何分歩く？」
   - ×「水中地形と戦略」 → ○「渚園はどこを狙う？石積みの先に広がる浅場の地形」
   - ×「安全・注意事項」 → ○「渚園で気をつけること｜アカエイとキャンプ場の決まり」
   - 記事の種類ごとの**節の役割と順番**は、各 `*-article/SKILL.md` のまま。変えるのは見出しの言葉だけ
2. **H2 だけを上から読んで、記事の話の流れが分かる**ようにする
3. **H2・H3 の直下の1〜2文（40〜80字）で、その見出しの答えを言い切る。** 理由と詳しい説明はその後ろに書く
   - この文は、そこだけ抜き出されても意味が通るように書く。「これは」「上で述べたとおり」で始めない。主語（場所名・魚種名）を省かない
   - 数字には単位と条件を付ける（「普通車は1日〇〇円」「〇月〜翌〇月は禁漁」のように、材料にある数をそのまま書く）。変わりうる事実には「2026年11月時点」のように時点を書く
4. **くらべる内容は表にする**（場所×魚、サイズ×料理法、時期×釣り方）。手順は番号つきの箇条書きにする
5. **「よくある質問」の H2 を、まとめの前に置いてよい。** 問いを H3 にして3〜5個、答えは2〜3文。問いは指示書の「材料」にある検索クエリから取る（自分で調べて足さない）。本文と同じ内容のくり返しになる問いは作らない
6. 既存の H2 を変えると、ページ内リンクの行き先（`#見出し`）が変わる。リライトで H2 を変えたら、同じ記事の中と、ほかの記事からのページ内リンクを検索して直す

## 6. 節の中と、節のつなぎ

1. **文だけの段落を4つ以上続けない。** 300字ごとを目安に、表・箇条書き・H3・Callout・画像のどれかを入れて、目が止まる場所を作る
2. **節の最後の1文で、次の節へつなぐ。** 読者が次に持つ疑問を、こちらから言う
   - 例: 「停める場所が決まったら、次は竿を出す位置です。」
   - 例: 「ここまでで時期と場所が決まりました。残るは仕掛けだけです。」
   - 「次の章では〜を解説します」という予告の形にしない。読者の疑問の形にする
3. **TackleCard の後ろにも1文を置く**（§2 の2）。カードで節を終わらせない
4. **図にしたほうが早い内容**（位置関係・手順・くらべるもの）には、画像のプロンプトを置く。目安は記事に1〜2枚。画像の決まりは `.workspace/codex/image-style.md`
5. **一番知りたい答えは最初に出し、深い話・得する話を後半にも1つ置く**（例: 地元の人が選ぶ時間帯、失敗しやすい点、持ち帰ってからの扱い）。冒頭の箇条書きでその話があることを予告しておくと、読者が後半まで進む理由になる。予告した話は必ず本文に書く

## 7. 長さ

- 文字数の下限は、これまでどおり各 SKILL に従う（通常の記事 2,000字、ポイント単体 3,000字）
- **通常の記事は 3,500字前後までを目安にし、5,000字を超えるなら理由が要る。** 6,000字を超えた記事は、最後まで届く人が14%まで落ちている
- 厚くするときは、足す前に削る。**同じ内容のくり返し・一般論・前置き・あいさつは削ってよい。** 事実（料金・場所・規則・筆者の記録）は削らない。削るか迷う事実は残して報告書に書く
- 1つの記事に検索の目的が2つ以上入っていて 5,000字を超えるときは、分割の案を報告書に書く（自分では分割しない）

## 8. 人の心の動きを使う書き方

使ってよいもの。どれも、書いてある事実だけで成り立たせる。

| 心の動き | 使い方 | 例 |
|---|---|---|
| 損をしたくない | 知らないと実際に困る事実を、早めに具体的に書く | 「この駐車場は〇時に門が閉まります。夕マズメまで粘る日は、もう一方に停めます。」（時刻は材料にあるもの） |
| 続きが気になる | 答えを出したうえで、次の疑問を投げる（答えを隠すのではない） | 「釣れるのは秋です。では、同じ秋でも釣れる日と釣れない日は何が違うのでしょうか。」 |
| 選択肢が多いと選べない | 候補は3つまで。「迷ったらこれ」を1つ言い切る | 「初めてなら砂揚げ場です。理由は3つあります。」 |
| 自分のことだと思うと読む | 冒頭の「こんな人に向いています」。節の頭で読者の状況を言う | 「小学生の子どもと行くなら」 |
| ゴールが見えると進む | 進み具合を伝える | 「準備はあと1つです。」 |
| 具体的なものは信じやすい | 「たくさん」「近い」を数に置きかえる | 「駐車場から歩いて〇分」（材料にある数） |
| 終わり方が印象を決める | まとめは本文のくり返しにしない。**次にやること1つ**と、次に読む記事1本で終える | 「まず週末の潮を確かめてください。」 |

**禁止**

- 答えを記事の後ろに隠す、タイトルの問いに答えない
- 根拠のない「必ず釣れる」「誰でも簡単」、うその「今だけ」「残りわずか」
- 不安をあおるだけで、対処を書かない
- 「みんな使っています」「大人気」など、材料にない評判
- 筆者の釣行・釣果・感想を作る（[writing-style/SKILL.md](writing-style/SKILL.md)「記事の体温」のとおり）

## 9. 知識の記事を楽しく読めるようにする

ルール・地形・生態・道具の解説のような、調べものの記事で使う。

1. **節を、読者が現場で出会う場面から始める。** 定義から始めない
   - ×「漁業権とは、漁業法に基づき…」 → ○「干潮の浜でアサリを見つけても、浜名湖では持ち帰れません。理由は漁業権です。」
2. **1つの節に、発見を1つ入れる。** 「意外に思われますが」「多くの人が逆に覚えています」と言える事実を、節の前半に置く（材料にある事実だけ）
3. **たとえを使う。** 専門の言葉は、身近なものに置きかえてから正式な名前を出す
4. **理由を必ず書く。** 「〜してください」だけにせず、「〜だからです」を続ける。理由があると覚えやすく、納得して次へ進める
5. **語り手の判断を入れる。** 「私ならこの潮では入りません」のような、専門家としての一言。釣行の話ではなく判断として書く
6. **問いかけは節に1回まで。** 続けると、まわりくどくなる

## 10. 仕上げの確認（報告書にこの表を書く）

リライト・新規とも、記事ごとに確かめて、報告書の「やったこと」に結果を書く。

| 確認すること | 基準 |
|---|---|
| タイトルの字数 | 36字以内。先頭15字以内に検索される言葉 |
| タイトルの案 | 3案と、選んだ理由（「変えない」指定の記事は不要） |
| summary | 70〜120字。1文目が答え |
| 冒頭の字数 | 300字以内（上限500字）。カードと大きな表がない |
| H2 の数 | 5〜8個。分類名だけの H2 がない |
| H2 直下の文 | すべての H2 で、最初の1〜2文が答えになっている |
| 節の終わり | H2 の直前がカードで終わっていない。次の節へつなぐ文がある |
| 文だけの段落 | 4つ以上続いていない |
| 本文の字数 | 元の字数 → 直した後の字数。5,000字を超えるなら理由 |
| 削ったもの | 削った段落の要点。迷って残した事実 |
| 変えた H2 | 元の見出し → 新しい見出し。ページ内リンクを直したか |

## 11. 効果の見方（CC）

- 記事ごとの滞在時間、最後まで届いた割合、`scroll_depth` の `percent`（25・50・75・100）、検索の CTR を、直す前後の同じ日数でくらべる（`hq/tools/analytics-fetch`）
- タイトルを変えた記事は、変更から7日以上たってから、同じ順位帯での CTR をくらべる
- 数字が悪くなった決まりは、この文書を直す。Codex は気づいた点を報告書の改善提案に書く
