# Cho! Hamanako — 週間 PDCA ワークフロー

## 概要

週次のアクセスデータ（GA4 / GSC）を読み込み、Check（分析・要因仮説）と Act（優先度付きタスク）を生成して `.workspace/.task/W{nn}-task.md` に書き出す。

**重要**: W37以降、GSCを Search Console UI から「ページ」「クエリ」の2枚に分けてエクスポートする運用に変わり、ページ×クエリの突合や直帰率・デバイス別分析ができなくなっていた（W24〜W28時点のGA4探索レポート形式では可能だった）。本SKILLは **W24〜W28形式への復元＋デバイス軸の追加** を前提にしている。取得時は必ず下記「Step 1」のレポート定義に従うこと。

---

## Step 1: データ取得

### ファイルパス規則

```
.workspace/access-data/2026/w{nn}/
  chohama-ga4-w{nn}.csv   ← GA4 探索レポート（自由形式）
  chohama-gsc-w{nn}.csv   ← GA4 探索レポート内の Search Console データソース（ランディングページ+クエリ文字列 統合）
```

ユーザーが週番号を指定したらそのフォルダを読む。指定がなければ `.workspace/access-data/2026/` 内で最新フォルダ（数値が最大の `w{nn}`）を選ぶ。

**禁止**: Search Console UI（search.google.com/search-console）から直接エクスポートする「ページ.csv」「クエリ.csv」形式は使わない。ページとクエリが分離され、4-Box分析に必要なクエリ内訳・アクティブユーザー・キーイベント列が失われるため。

### GA4 探索レポート定義（自由形式）

- **ディメンション**: `ページタイトル` / `ランディングページ + クエリ文字列` / `新規/既存` / `デバイスカテゴリ`
- **指標**: `総ユーザー数` `アクティブユーザー` `表示回数` `直帰率` `セッションあたりの平均エンゲージメント時間` `キーイベント`
- **セグメント（横並び列）**: `すべてのユーザー` / `オーガニック検索` / `モバイル` / `デスクトップ`
  - 旧「ウェブのトラフィック」セグメントは廃止し `デスクトップ` に統一する（用途が曖昧だったため）

最初の7行はコメントヘッダー。9行目がサマリー行（`,,, 218, 206, ...`）。

### GSC CSV 構造（GA4探索 + Search Console データソース）

| 列 | 内容 |
|----|------|
| ランディング ページ + クエリ文字列 | URL（行 = ランディングページ、クエリで内訳展開可） |
| Google のオーガニック検索のクリック数 | オーガニッククリック |
| Google のオーガニック検索の表示回数 | インプレッション |
| Google のオーガニック検索のクリック率 | CTR（小数） |
| Google のオーガニック検索の平均掲載順位 | 検索順位（小さいほど上位） |
| アクティブ ユーザー | GA4 側のアクティブユーザー数 |
| エンゲージのあったセッション数 / エンゲージメント率 / イベント数 / キーイベント | 補助指標（Actの優先度判断に使用） |

最初の数行にコメントヘッダー（`# ---`）がある。スキップして8行目以降を読む。
2行目（ヘッダー行）の後の最初のデータ行（`,119,...,総計`）が全体サマリー。

ページ単位の行の下に、そのページで表示回数の多いクエリを確認できる場合は展開して読み、「優先A（タイトル改善）」の具体的な改善キーワードを特定する材料にする。

---

## Step 2: 指標の読み取り（サマリー行）

### GA4 サマリーから抽出

- **総ユーザー数**（すべてのユーザー）
- **表示回数**（= PV）
- **直帰率**（小数 → %変換） — `すべてのユーザー` と `モバイル` の両方を記録
- **セッションあたりの平均エンゲージメント時間**（秒）
- **キーイベント数**（コンバージョン。`affiliate_click` = TackleCardクリック）

### GSC サマリーから抽出

- **総クリック数**
- **総表示回数**
- **全体 CTR**
- **全体平均掲載順位**

---

## Step 3: GSC 4-Box 分析

表示回数 ≥ 5 のページを対象に分類する。

| 区分 | 条件 | アクション |
|------|------|----------|
| **優先A** 高順位×低CTR | 順位 ≤ 5 かつ CTR < 全体CTR | タイトル・meta desc 改善（該当ページのクエリ内訳から改善見出し語を抽出） |
| **優先B** 低順位×高CTR | 順位 > 8 かつ CTR ≥ 全体CTR | 本文強化・内部リンク追加 |
| **維持** 高順位×高CTR | 順位 ≤ 5 かつ CTR ≥ 全体CTR | 現状維持・内部リンク受け側に活用 |
| **要観察** 低順位×低CTR | 順位 > 8 かつ CTR < 全体CTR | コンテンツ見直しまたは放置 |

「未クリック高順位（CTR 0%）」があれば別途抽出して Act に追加。

---

## Step 4: GA4 LP Top 分析

GA4 CSV から「すべてのユーザー」セグメントの表示回数上位5ページを抽出。
各ページについて記録する：

- URL
- PV（表示回数）
- 直帰率（すべてのユーザー / モバイル 両方）
- 平均エンゲージメント時間
- キーイベント数（affiliate_click 発生有無）

直帰率が 90% 超えのページは「リライト候補」として Act に追記。
**モバイル直帰率が「すべてのユーザー」より明確に高いページ**は、現地閲覧（釣行前後のスマホ確認）を想定した表示崩れ・読了性の問題として別途フラグする。

---

## Step 5: Check セクションの生成

```markdown
### Check（W{nn} 分析・要因仮説）

- **数値変化**: ユーザー数 {前週} → {今週}（{±%}）、PV {前週} → {今週}（{±%}）。
  CTR {前週%} → {今週%}（{±%}）、平均滞在時間 {前週} → {今週}（{±%}）、
  直帰率 {前週%} → {今週%}（{±%}）、掲載順位 {前週} → {今週}（{±}）。
- **デバイス差**: モバイル直帰率 {x%} / デスクトップ直帰率 {y%}（乖離が大きい場合は明記）
- **CV（キーイベント）**: affiliate_click（TackleCardクリック） {前週} → {今週}件
- **LP Top流入**: （上位ページとPV）
- **要因仮説**: （データから読み取れる仮説）
- ⚠️ **データ制約**: （比較元・計算上の注意点があれば記載）
```

前週データがない場合は「前週比 データなし（初回計測）」と記載。

---

## Step 6: Act セクションの生成

```markdown
### Act（W{nn} → W{nn+1} タスク）

- [ ] {優先A ページ URL}（表示回数{n}・順位{x}・CTR{y}%、関連クエリ:{q}）→ タイトル・meta desc 改善（優先度：高）
- [ ] {優先B ページ URL}（表示回数{n}・順位{x}・CTR{y}%）→ 本文強化・内部リンク追加（優先度：中）
- [ ] {直帰率90%超ページ} → 導入文・タイトルのリライト（優先度：中）
- [ ] {モバイル直帰率が突出して高いページ} → モバイル表示・読了性の確認（優先度：中）
- [ ] {affiliate_click が0件のPV上位ページ} → TackleCard配置・訴求文の見直し（優先度：中）
- [ ] 前週 Act の未完了タスクを task.md から引き継ぎ（必要なら記載）
```

タスクは **優先度：高 → 中 → 低** の順に並べる。

---

## Step 7: ファイル出力

出力先: `.workspace/.task/W{nn}-task.md`

```markdown
# W{nn} アクセス解析から次にやるタスク

主にサイト改善の項目が該当する。

### Check（W{nn} 分析・要因仮説）
{Step 5 の内容}

### Act（W{nn} → W{nn+1} タスク）
{Step 6 の内容}
```

ファイルが既に存在する場合は上書きせず、ユーザーに確認する。

## データ制約の扱い（既知の問題）

| 制約 | 対処 |
|------|------|
| GA4 に「デフォルトチャネル」次元がない | チャネル別セグメントは空欄と明記 |
| 指標粒度が週をまたいで異なる（セッション vs ページ） | 前週比滞在時間の比較には注意書きを追加 |
| 新規 vs リピーターの UU は重複計上になる | PV 加重平均の直帰率を代替値として使用 |
| 表示回数が少ない（< 5）URL | 4-Box 分析から除外し、「サンプル不足」と記載 |
| GSC を「ページ.csv」「クエリ.csv」の分離形式で取得してしまった場合 | ページとクエリのURL/クエリテキストを手動突合してから分析する旨を Check に注記する（本来は Step 1 のGA4探索形式で再取得を推奨） |
