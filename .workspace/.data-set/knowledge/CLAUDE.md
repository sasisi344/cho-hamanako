2026-11-27 作成（ユーザー決定）。記事のために調べたことは、ここにカテゴリ分けして残し、記事の frontmatter `research:` から指す。**同じ事実をウェブで調べるのは1回だけにする**ため。設計の正本は `344blog/hq/.workspace/herness-project.md` §7（このリポジトリの外。ここだけで作業できるように要点を写してある）。

## 1. 探す（調べる前に必ず）

1. `index.md` を開き、カテゴリの表で題と別名を見る
2. 見つからなければ `rg -n "<語>" .workspace/.data-set/knowledge`（表記の揺れも試す: ハゼ／マハゼ、今切口／今切れ）
3. 使えるかは `状態` で決める

| 状態 | 記事の根拠にしてよいか |
|---|---|
| 事実の表 | 期限内の行はそのまま使う（ウェブで調べ直さない）。期限切れの行だけ調べ直す |
| 旧メモ（出典URLあり・表なし） | 手がかり。使う事実は、出典を開いて確かめ、§3 の表に移してから使う |
| 旧メモ（出典なし） | 手がかりだけ。数値・料金・規則・日程は一次情報で確かめ、表に移してから使う。地元の傾向（釣れる場所・時期）は筆者の知見として扱い、断定の強さを上げない |

## 3. 1トピック1ファイルの形

```markdown
---
id: hm-places-imagireguchi        # hm-<カテゴリ>-<slug>。記事の research: から指す名前
title: 今切口
category: places
aliases: [今切れ, 今切口 舞阪側]
updated: 2026-11-27               # 最後に事実を確かめた日
---

## 事実

| ID | 主張 | 値 | 出典 URL | 確認日 | 期限 |
|---|---|---|---|---|---|
| F01 | 遊漁禁止の範囲 | 導流堤の南側から… | https://… | 2026-11-27 | 2027-11-27 |

## メモ（事実ではないこと: 経緯、出典どうしの食い違い、取れなかったこと）
```

- 1つの事実は1行。出典 URL と確認日のない行は書かない（取れなかったものはメモに「未確認」）
- Googleマップの評価・件数は書かない（その日に開き直すもの）
- 旧メモ（`status: legacy`）の事実を確かめたら、同じファイルに `## 事実` の表を足し、`status: legacy` の行を消して `updated:` を書く。旧メモの本文は消さずに残してよい
- 新しいトピックは `index.md` の別名でかぶりがないか確かめてから作る

## 4. 記事から指す

```yaml
research:
  - hm-places-imagireguchi          # トピックごと
  - hm-rules-yugyo#F02,F05          # 使った行だけ
```

- アウトラインの「事実の材料」に ID を書き、書く係がそのまま記事の frontmatter に写す。公開のあとも消さない
- ここにない事実を記事に書かない（書く係）。照合する係は、`research:` の行と本文の数値を突き合わせ、「一致」の行は調べ直さない
