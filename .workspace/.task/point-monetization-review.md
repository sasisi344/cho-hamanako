## 結論サマリ

1. **「分離」ルールは、アクセスのある記事から収益の接点を外す結果になっている。** ポイント記事は検索クリックの約3割を集めているが、そのうち63%は**アフィリエイトが0枚の記事**に着地している。受け皿のはずの travel 記事は検索クリックがほぼ0件。
2. **ポイント記事 → BlogCard → target/travel 記事 → アフィリエイト、という2段の導線**は成立していない。travel 記事へ BlogCard を置いているポイント記事は77本中5本だけ。BlogCard は「関連記事」に見えるため、読者がクリックする理由もない。
3. **ルールと実装がずれている。** SKILL ではポイント記事の TackleCard を禁止しているが、実際には26本に設置されている。多くは記事末尾の「推奨タックル」節に汎用の4枚セットを並べたもので、そのスポットならではの理由がない。
4. **旅行系リンクは、楽天トラベル・じゃらんのトップページに飛ぶ汎用リンク**。「浜名湖で泊まる」という文脈とリンク先がつながっていない。
5. **クリックが少ないことは、まだ数値で確認できていない。** `affiliate_click` は4週連続で0件。計測の不具合なのか本当に0なのか切り分けられていない（W42 Act の高優先タスクで確認待ち）。

→ 提案: ルールを「分離」から「**役割分担＋橋渡し**」に変える。ポイント記事には「**この釣り場だから必要なもの**」に限り、誘導文付きでアフィリエイトを置けるようにする。深い比較・レビューはこれまでどおり target 記事が受け持つ。

## 2. 「分離」施策の効果が出ない原因

### 2.1 前提の誤り: 読者は2段の導線を進まない

分離ルールは「ポイント記事で集客し、BlogCard で target/travel 記事へ送り、そこで収益化する」という前提で作られている。しかし次の理由で成立していない。

| 想定 | 実際 |
|---|---|
| ポイント記事の読者は道具・宿の記事へ移動する | ポイント記事の読者が知りたいのは「どこで・いつ・どう釣るか」。読み終えた時点で目的は達成していて、次の記事に移る動機がない |
| BlogCard が橋渡しになる | BlogCard は「関連記事」の見た目。押す理由（何が分かるか、なぜ今読むべきか）が書かれていない |
| target/travel 記事にアクセスが集まる | travel は検索クリック0件。ポイント記事からの内部流入も、BlogCard が5本にしかないので少ない |

**→ 2段の導線では各段で読者が離れ、最後のアフィリエイトにはほぼ届かない。**

### 2.2 「無駄な記事を減らす」と「収益化」を同じルールで扱った

- 分離ルールの目的は、ポイント記事に物販を詰め込んだ薄い記事を作らないことだった。この目的は達成できている。
- 一方で、**収益化の接点をアクセスのない記事に移した**ことになり、売上につながる場所がなくなった。
- 本来は「記事を増やさない」ルールと「アクセスのある記事で収益化する」ルールは両立できる。分ける必要があったのは記事ではなく、**ポイント記事内での役割**だった。

### 2.3 ルールのあいまいさで、どちらも中途半端になった

- SKILL ではポイント記事の TackleCard を「禁止」しているが、`*-fukabori`（魚種×ポイントの深掘り）やハブ記事、一部のスポット記事には置かれている。
- 結果として「純粋な攻略情報」にも「誘導できる収益ページ」にもなっていない。汎用4枚セットが記事末尾にまとまって置かれている。

### 2.4 誘導文の型がない

- writing-style・point-article・target-article のどのルールにも、「**カードの直前に何を書けばクリックされるか**」の型がない。
- 旅行系は [travel-affiliate-optimization.md](travel-affiliate-optimization.md) で「本音転換点」の考え方を定義しているが、travel 記事にしか適用されておらず、アクセスのあるポイント記事には広がっていない。

## 3. 改善方針

### 3.1 ルールを「分離」から「役割分担＋橋渡し」へ

| 記事 | 役割 | アフィリエイトの扱い |
|---|---|---|
| ポイント記事（スポット） | 集客と「行く」決断の後押し | **このスポットで必要になるもの**だけ、最大3枚。各カードに誘導文が必須。汎用の道具一覧は置かない |
| ポイント記事（ハブ・条件別） | 条件で選ぶ読者の入口 | 条件に直結するもの（車横付け→クーラー・電源、ウェーディング→ウェーダー・エイガード）を条件の説明の直後に置く |
| `*-fukabori` | 魚種×ポイントの攻略 | 現状どおり設置可。二層マッチング（王道／地元）に従う |
| target 記事 | 道具の比較・選び方の深掘り | 比較表と複数カード。ポイント記事からの「もっと比べたい人」の受け皿 |
| travel 記事 | 旅行プランの提案 | 宿・体験・レンタカー。ポイント記事からは「遠方から来る人」向けの導線で送る |

### 3.2 ポイント記事で使う「必要が生まれる場面」の型

アフィリエイトは、**読者が「それが必要だ」と気づく節の中**に置く。記事末尾にまとめて置かない。

| 記事内の節 | 必要が生まれる場面 | 置くもの（例） |
|---|---|---|
| 駐車場・アクセス | 車横付けできる／駐車場から遠い | クーラー、キャリーカート、ポータブル電源 |
| 足場・地形 | 足場が高い／ゴロタ／ウェーディング | タモ、スパイクシューズ、ウェーダー、エイガード |
| 時間帯 | 夜釣り・朝マズメが主体 | ヘッドライト、電気ウキ |
| 安全・注意 | アカエイ・毒魚がいる | エイガード、フィッシュグリップ、ライフジャケット |
| 近くの施設 | 釣具店が遠い／エサの調達が難しい | 事前に買えるエサ・仕掛けセット（＋エサ自販機記事への BlogCard） |
| 遠方からの釣行（地区需要のあるスポット） | 朝マズメに合わせて前泊したい | **エリアを指定した**宿泊リンク、近くの体験・観光 |

### 3.3 誘導文テンプレート（カードの直前に1〜3文）

**状況 → 困ること → 解決 → カード**の順で書く。

> 例（渚園・夏のチヌトップ）
> 渚園の砂浜側は遠浅で、ウェーディングで沖の導流堤まで攻めるのが定番です。ただ、夏の夕マズメは足元にアカエイが寄ってきます。膝下までのウェーディングでも、エイガードは必ず着けてください。
> `<TackleCard id="seabass/little-presents-ray-guard-oa-24" />`

> 例（遠方からの釣行・宿泊）
> 今切口の朝マズメは日の出前から始まります。県外から来るなら、弁天島・舞阪周辺に前泊すると、薄暗いうちに釣り座に入れます。
> `<TackleCard id="travel/xxx-bentenjima-stay" />`（※エリア指定リンクを新規作成）

**禁止する書き方**
- 「おすすめのタックルはこちら」だけの導入
- スポットと関係のない汎用カードの羅列
- 1つの節に3枚以上のカードを並べる

### 3.4 BlogCard にも誘導文を付ける

target・travel 記事への BlogCard の直前には、**読むと何が分かるか**を1文で書く。

> 例: ウェーダーの選び方（夏用・冬用の違い、サイズの合わせ方）は別の記事で比べています。
> `<BlogCard slug="..." />`

### 3.5 旅行系アフィリエイトの作り直し

- 楽天トラベル・じゃらん・asoview! で**エリアを指定したディープリンク**（舘山寺温泉、弁天島・舞阪、浜名湖北部など）を作成し、`src/content/affiliates/travel/` に追加する（ASP 管理画面での作成はユーザー作業）。
- バナーよりテキストリンクのほうがクリックされやすいため、ポイント記事では**テキスト版を優先**する（`BannerCard` はテキスト版にも対応しているか要確認）。
- 対象は地区需要のあるスポットに絞る（新居・舞阪・弁天島・舘山寺・猪鼻。[point-restructure-policy.md](point-restructure-policy.md) §3 を参照）。

## 5. データ上の注意

- W42 の GA4 は計測方法の切り替え（10/5夜）をまたぐ週。PV・ランディングの比率は参考値にとどまる。
- GSC はページ.csv の7日間分のみ。1記事あたりのクリックは数件〜十数件で、記事単位の差は誤差の範囲。区分別の比率（ポイント31%、カードなし記事に63%）は傾向として読む。
- アフィリエイトのクリックと成果は計測できていないため、本レポートの「クリックされにくい」は、ユーザーの体感と構造（設置数・位置・導線）からの推定。
- 「旅行系のリンクがポイント記事にある」という前提は、実際には BlogCard 経由（5本）でのこと。ポイント記事に `travel/*` カードを直接置いた例はない。
