# H-44 CTR を戻すタスクの進め方（2026-11-20）

分析の結果: `.workspace/.task/h44-ctr-analysis.md`

## 基本方針（ユーザー指示 2026-11-20）

**クリックが少ないと感じたら、先に競合を検索して自分の記事とどこが違うかを分析し、それから打ち手を決める。** 数字だけ見てタイトルを書き換えない。

理由: 順位が同じでも CTR が低い原因は、タイトル以外にもある（AI の概要・ページ内リンク・画像・動画・地図など検索結果の画面、上位の記事の切り口、検索意図とのずれ）。違いを確かめずに直すと、外れた打ち手になりやすい。

## 1記事の進め方

1. **数字で対象を決める**（CC）
   - GSC のページ×クエリで、表示が多いのに CTR が順位の割に低い記事を選ぶ。目安は前年の順位帯ごとの CTR（分析ファイルの表）
   - 主なクエリを3〜5個にしぼる
2. **競合の検索結果を見る**（CC、主なクエリごと）
   - 実際に検索して、上位5位前後の記事と検索結果の画面を記録する
   - 見ること:
     - タイトル: 数字・地名・季節・年、言い切りか問いか、読者の得が前半にあるか
     - description の書き方（検索結果に出ている文）
     - 画面の部品: AI の概要、ページ内リンク、強調スニペット、画像・動画、地図、「他の人はこちらも質問」
     - 上位の記事の切り口: 検索した人が一番知りたいことに、何を先に答えているか
     - 自分の記事の検索結果での見え方（タイトルが切れていないか、日付、description が意図どおり出ているか）
   - 一次情報（釣行の体験など）が足りないと分かったら、見送らずユーザーへの質問にする
3. **違いを1枚にまとめる**（CC）
   - 「自分の記事／上位の記事／違い／直せるか」の表。直せないもの（AI の概要など）は分けて書く
4. **打ち手を決める**（CC が案、必要ならユーザーが判断）
   - タイトル・description だけか、冒頭・見出しまで直すか
   - タイトルは `.agents/reader-flow-rules.md` §3 の型で書く
5. **指示書 → Codex → 検収**（`hq/org/README.md` の流れ）
   - 指示書に、2〜3 の比較表と、変えてはいけないこと（例: キビレは刺身を勧めない）を載せる
6. **公開して測る**
   - 変更日の前後28日でくらべる（`fetch.mjs compare --page <slug> --change <日付>`）
   - `.task/schedule-task.md` に測定日を載せ、月次分析でまとめて見る
   - 同じ時期にサイト全体の変更（目次など）を入れると効果を分けられないので、時期をずらす
